# Adversarial test matrix (ECO-022 T01–T22)

Status: v1, 2026-11-06, #27. The source is Drive **ECO-022 v1.0**, "Adversarial test matrix" (case wording is
paraphrased here). Every case is either a test, a partial test with its remainder linked to a work package, or
"not yet modelled" with the work package that will model it. **A row is only as true as its linked test.** When a
linked WP merges, its owner updates the row in the same PR.

Status key:
- **COVERED:** an executable test pins the case against the current code.
- **PARTIAL:** the invariant is pinned at one layer (usually `@fle/domain`), but the mechanism the case describes
  doesn't exist in the engine yet.
- **NOT YET:** no mechanism; the linked issue owns it.

Test paths are relative to `packages/`. Test names are quoted so you can grep for them.

## Mutation spot-checks (are the tests able to fail?)

Rerun them with `bash scripts/qa/mutation-spot-check.sh` from the repo root (it needs bash, so use Git Bash on Windows).
Each check breaks one guard with `sed`, runs the targeted test files, and restores the file. A check whose
`sed` pattern no longer matches prints `MUTATION DID NOT APPLY`. Update the pattern; don't delete the check.

## Keeping it true

- A PR that adds a mechanism for a NOT YET or PARTIAL row updates the row and links its test.
- A golden-hash or invariant change that touches a COVERED row needs the reason in the PR description.
- Re-run the mutation spot-checks when a guard listed above is refactored.
